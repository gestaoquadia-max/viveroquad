## 1. Como ler esta matriz

### 1.1 Colunas

Cada linha é uma funcionalidade. As colunas são: **Cód.** (AL = aluno, PR = professor, AD = admin N.P.P., TR = transversal) · **Perfil** · **Área** · **Funcionalidade** · **Descrição** (1 linha) · **Implementação atual** (1 linha, prefixada pelo código de maturidade) · **Classificação** (vocabulário obrigatório da auditoria) · **Arquivos e funções** (linhas aproximadas do `src.html`, salvo indicação) · **Dados necessários** (no sistema real) · **Sistema futuro responsável** (do ecossistema previsto) · **Prio.¹** · **Dependências** · **Decisão pendente** · **Observações**.

¹ **Prioridade é SUGESTÃO do auditor**, não decisão: P1 = núcleo indispensável para um piloto/V0 real; P2 = sequência imediata pós-piloto; P3 = pode esperar (V1/V2 ou acessório).

### 1.2 Código de maturidade (prefixo da coluna "Implementação atual")

| Código | Significado |
|---|---|
| **[D]** | Pronta apenas para demonstração — render fixo, sem mecânica (em geral APENAS VISUAL) |
| **[S]** | Simulada de forma convincente — mecânica completa em memória JS; zera ao recarregar (F5) |
| **[P]** | Parcialmente funcional localmente — mecânica incompleta, vestigial ou inalcançável pela interface |
| **[R]** | Dependente de reconstrução — o que existe não serve de base técnica para o sistema real |
| **[I]** | Dependente de integração — a mecânica local vale como especificação; falta ligar back-end/sistema externo |
| **[V1] / [V2]** | Prevista apenas para V1 ou V2 — hoje placeholder "EM BREVE" ou inexistente no código |

Combinações são comuns (ex.: **[S+I]** = simulada de forma convincente E dependente de integração). O protótipo inteiro roda 100% no navegador: **toda** linha "[S]" pressupõe, no sistema real, persistência e validação no servidor.

### 1.3 Vocabulário de classificação (obrigatório)

CONFIRMADO NO CÓDIGO · APENAS VISUAL · SIMULADO LOCALMENTE · DEPENDE DO FRONT-END REAL · DEPENDE DO BACK-END · DEPENDE DE BANCO DE DADOS · DEPENDE DE SISTEMA EXTERNO · HIPÓTESE · DECISÃO DE PRODUTO PENDENTE · DECISÃO TÉCNICA PENDENTE · DIVERGÊNCIA DOCUMENTAL. Um item pode ter mais de um rótulo.

### 6.2 O que NÃO existe em lugar nenhum (nem simulado)

Persistência de qualquer dado de negócio entre sessões · autenticação real · telemetria/log de eventos (pré-requisito de V0 no PDF §8) · IRA · push · geofencing · chat de duas vias · extração real de PDF · leitura real de QR/câmera · pagamento real. Tudo isso é DEPENDE DO BACK-END / DEPENDE DE SISTEMA EXTERNO e está apenas prometido em texto ou marcado `[INTEGRAÇÃO REAL]` no fonte.

### 6.3 Divergências que afetam a leitura da matriz

1. **Economia ativa na V0** (AL-25/AL-28): o documento-base fasea a economia para V1-A/B/C; o protótipo demonstra tudo, inclusive Diamante (dinheiro real), que não existe na rev. 2.3 — DECISÃO DE PRODUTO PENDENTE (corte do piloto e rev. 2.4).
2. **Tutorial** (AL-05): 9 passos (docs) × 19 etapas (dec. 17) × 29 passos reais no código; e a dec. 105 ("abre em todo acesso") é contradita por `vq_tut_skip`.
3. **Gate N.P.P.** (AD-01): o e-mail não é validado — só a chave `NPP-2026`.
